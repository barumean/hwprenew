# 프로젝트 점검 및 개선 제안

## 점검 요약

이 프로젝트는 `표정리.py` 단일 실행 파일과 `서식규칙.yaml` 규칙 파일을 중심으로 HWP/HWPX 문서의 표, 그림틀, 사진 개체 서식을 일괄 정리하는 자동화 도구입니다. 현재 구현은 원본 문서를 직접 수정하지 않고 `_정리본` 사본을 저장하며, 표 구조 분석은 HWPX XML 파싱을 사용하고 실제 서식 적용은 pyhwpx/한글 COM 자동화를 사용하는 하이브리드 구조입니다.

## 강점

- 원본 보호 원칙이 명확합니다. 처리 결과는 입력 파일과 같은 폴더의 `_정리본` 파일로 저장됩니다.
- 사용자 설정이 한국어 YAML 키로 구성되어 비개발자도 규칙을 조정하기 쉽습니다.
- 셀 병합 구조를 HWPX XML에서 분석해 COM 단독 접근보다 표 구조 인식 안정성이 높습니다.
- 한글 COM의 왼쪽 테두리 색상 누락 문제를 HWPX 후처리로 보정하는 우회 로직이 포함되어 있습니다.
- 표/그림틀/사진 너비 조절, 개체 번호종류, 글자처럼 취급, x 스타일 제거까지 실무 문서 정리에 필요한 부가 기능이 포함되어 있습니다.

## 리스크 및 한계

| 영역 | 현재 상태 | 영향 |
|---|---|---|
| 실행 환경 | Windows + 한글 + pyhwpx + pyyaml 필수 | Linux/macOS/CI에서는 실제 HWP 처리 검증이 어렵습니다. |
| 의존성 관리 | 패키지 요구사항이 문서에만 존재 | 신규 사용자가 설치할 패키지를 놓칠 수 있습니다. |
| 테스트 자동화 | 단위 테스트/샘플 기반 회귀 테스트 없음 | 규칙 파싱, XML 후처리 수정 시 회귀 위험이 있습니다. |
| 다중 구역 문서 | 첫 구역 편집 영역 폭만 사용 | 구역별 용지/여백이 다른 문서에서 너비가 의도와 다를 수 있습니다. |
| 중첩 표 | 분석 순서와 컨트롤 순서가 어긋날 수 있음 | 복잡한 문서는 일부 표가 건너뛰어질 수 있습니다. |
| 결과 리포트 | 콘솔 출력 중심 | 배치 처리·감사 기록·사용자 전달용 리포트로 활용하기 어렵습니다. |

## 우선순위별 개선 제안

### P1. 의존성 설치 절차 고정

- `requirements.txt`를 기준으로 `pip install -r requirements.txt` 설치 절차를 안내합니다.
- Windows/한글 미설치 환경에서 `pyhwpx` 기능을 실행하지 않고도 규칙 파싱만 검증하는 경량 테스트를 분리합니다.

### P2. 규칙 파싱 단위 테스트 추가

- `hex_to_hwp_color`, `mm_to_hu`, `parse_width_rule`, `parse_line_rule`, `load_rules`를 대상으로 pytest 테스트를 추가합니다.
- 잘못된 색상, 잘못된 선 종류, 잘못된 너비 입력이 `규칙오류`로 명확히 실패하는지 검증합니다.

### P3. 검사 전용 모드 추가

- `python 표정리.py --검사 문서.hwp` 형태로 저장 없이 표 개수, 그림틀 수, 사진 수, 적용 예정 규칙을 출력합니다.
- 실제 문서 변경 전 영향 범위를 확인할 수 있어 운영 안정성이 높아집니다.

### P4. 변경 리포트 파일 저장

- 콘솔 요약 외에 JSON/Markdown 리포트를 저장합니다.
- 예: 처리 표 수, 실패 표 인덱스, 너비 불일치 수, 제거한 스타일 목록, 출력 파일 경로.

### P5. 배치 처리 지원

- 폴더 입력 시 `.hwp`, `.hwpx` 파일을 순회 처리하고 파일별 성공/실패 결과를 리포트에 누적합니다.
- 여러 문서를 반복 정리하는 실제 업무 흐름에 적합합니다.

### P6. 구역별 문서폭 대응

- 현재 `문서폭` 기준은 첫 구역의 편집 영역 폭으로 계산됩니다.
- 장기적으로는 표가 속한 section의 `PageDef`를 추적해 구역별 목표 너비를 적용하는 방식이 더 정확합니다.

## 이번 점검에서 반영한 개선

- Python 런타임 의존성을 명시하는 `requirements.txt`를 추가했습니다.
- 프로젝트 운영자가 우선순위를 정하기 쉽도록 점검 결과와 개선 제안을 문서화했습니다.

## 권장 다음 작업

1. `pip install -r requirements.txt`로 Windows 실행 환경의 의존성 설치 절차를 검증합니다.
2. 규칙 파싱 단위 테스트를 추가해 한글/COM이 없는 환경에서도 기본 품질 검사를 가능하게 합니다.
3. 검사 전용 모드와 변경 리포트 저장 기능을 먼저 구현해 실제 문서 적용 전 안정성을 높입니다.
