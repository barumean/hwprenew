# HWP 서식 일괄정리 보조프로그램 기획서

작성일: 2026-07-09 (초안 v0.1)

---

## 1. 배경과 목적

한글(HWP/HWPX) 문서를 여러 사람이 편집하거나 여러 출처에서 취합하다 보면 표의 테두리 선 굵기·종류, 셀 배경색, 글꼴·크기·색 같은 서식이 제각각이 된다. 이를 손으로 하나씩 고치는 작업은 시간이 많이 들고 누락이 잦다.

**목적**: 한글 문서를 읽어들여 미리 정의한 "표준 서식 규칙(프리셋)"에 따라 **표 서식(테두리 선, 배경 등)과 글자 서식을 일괄 정리**해 주는 보조프로그램을 개발한다.

### 스펙 문서에서 확인한 핵심 사실

- HWP 5.0에서 **테두리/배경(`HWPTAG_BORDER_FILL`)과 글자 모양(`HWPTAG_CHAR_SHAPE`)은 문서 정보(DocInfo)에 목록으로 중앙 저장**되고, 본문의 각 셀·글자 구간은 그 목록의 ID를 참조한다.
  → 서식 일괄정리는 개념적으로 **"표준 서식 정의를 만들고, 본문 참조 ID를 표준 정의로 재매핑"** 하는 작업이다. HWPX(OWPML XML)도 동일한 구조(`header.xml`의 `charProperties`, `borderFills`)를 가진다.
- **배포용 문서**는 본문 스트림이 AES-128로 암호화되어 있다 → 1차 범위에서 제외하고 "지원 불가" 안내 처리.
- 수식·차트는 별도 개체 구조 → 서식 정리 대상에서 제외(건드리지 않고 보존).

## 3. 핵심 설계 결정: 문서 접근 방식

세 가지 방식을 비교한다.

| | A. COM 자동화 (한글 프로그램 제어) | B. HWPX 직접 조작 (zip+XML) | C. HWP 바이너리 직접 조작 (hwplib류) |
|---|---|---|---|
| 원리 | 설치된 한글을 pywin32/pyhwpx로 조종 | .hwpx 압축을 풀어 OWPML XML 수정 | .hwp OLE 구조를 직접 파싱·재작성 |
| 지원 형식 | .hwp, .hwpx 모두 | .hwpx만 | .hwp만 |
| 전제 조건 | Windows + 한글 설치 필수 | 없음 (순수 Python 가능) | 없음 (단 Java) |
| 저장 결과 신뢰도 | **최상** (한글 엔진이 저장) | 높음 (스키마만 지키면 안전) | 위험 (바이너리 재작성 버그 시 파일 손상) |
| 속도(대량 처리) | 느림 (UI 자동화 수준) | 빠름 | 빠름 |
| 구현 난이도 | 낮음~중간 | 중간 | 높음 |

**권장안: A(COM)로 시작하고, B(HWPX)를 2단계 엔진으로 추가하는 하이브리드.**

- 사용 환경이 Windows 11이고 HWP 문서를 다루는 이상 한글이 설치되어 있을 가능성이 높다. COM 방식은 "한글이 직접 저장"하므로 결과물이 깨질 걱정이 없고, .hwp/.hwpx를 가리지 않는다. hwp-mcp라는 검증된 선례도 있다.
- 이후 대량 배치 속도가 문제되거나 한글 미설치 환경 지원이 필요해지면, HWPX 직접 엔진(B)을 추가한다. .hwp 파일은 COM으로 .hwpx 일괄 변환 후 B 엔진으로 처리하는 경로도 가능하다.
- C(바이너리 직접 쓰기)는 위험 대비 이득이 없어 채택하지 않는다. (읽기 전용 분석 용도로만 참고)

## 4. 기능 요구사항

### 4.1 MVP (1차 목표)

| # | 기능 | 설명 |
|---|---|---|
| F1 | 서식 규칙 프리셋 | YAML/JSON 파일로 표준 서식 정의 (§5). 프리셋 여러 개 저장·선택 가능 |
| F2 | 표 서식 일괄 적용 | 문서 내 모든 표에 대해: 바깥 테두리(선 종류/굵기/색), 안쪽 선, 머리글 행 배경색·글자 처리, 본문 셀 배경 제거/통일 |
| F3 | 글자 서식 일괄 적용 | 본문·표 안 텍스트의 글꼴, 크기, 글자색, 진하게/기울임 정리 (전체 통일 또는 "허용 목록 외 서식만 교정" 선택) |
| F4 | 일괄(배치) 처리 | 파일 여러 개 또는 폴더 단위 처리 |
| F5 | 원본 보호 | 처리 전 원본 자동 백업(사본 저장), 원본 덮어쓰기는 옵션 |
| F6 | 변경 리포트 | 파일별로 무엇을 몇 건 바꿨는지 로그/리포트 출력 |
| F7 | 검사 전용 모드 | 수정 없이 규칙 위반 항목만 찾아 보고 (dry-run) |

### 4.2 2차 이후 (확장)

- 머리글 행 자동 인식 고도화(1행 고정 → 병합/음영 패턴 기반 추론)
- 문단 서식(정렬, 줄간격, 들여쓰기) 정리
- HWPX 직접 엔진(고속 배치, 한글 미설치 환경)
- 간단한 GUI(파일 드래그앤드롭, 프리셋 선택, 결과 미리보기)
- MCP 서버화 → Claude 등 AI에서 "이 문서 표준서식으로 정리해줘" 형태로 호출
- 스타일(문단 스타일) 기반 정리: 서식을 직접 덮는 대신 표준 스타일을 정의하고 연결

### 4.3 범위 제외 (Non-goals)

- 배포용 문서(암호화), 암호 걸린 문서 → 감지 후 건너뛰고 리포트에 표기
- 수식·차트·그림 개체 내부 서식 → 보존만 하고 건드리지 않음
- HWP 3.0 등 구버전 형식 → 한글에서 열리면 COM 경로로는 자연히 처리됨, 별도 대응 없음
- 문서 내용(텍스트) 변경 — 서식만 다룬다

## 5. 서식 규칙(프리셋) 설계 초안

```yaml
# preset-standard.yaml (예시)
name: 표준 보고서 서식
table:
  outer_border: { type: solid, width: 0.4mm, color: "#000000" }
  inner_border: { type: solid, width: 0.12mm, color: "#000000" }
  header_row:
    detect: first_row          # 1행을 머리글로 간주 (v1)
    background: "#D9D9D9"
    bold: true
    align: center
  body_cell:
    background: none           # 본문 셀 배경 제거
text:
  scope: all                   # all | table_only | body_only
  font: "함초롬바탕"
  size: 10pt
  color: "#000000"
  keep_emphasis: true          # 기존 진하게/기울임/밑줄은 유지
```

- 규칙은 "강제 통일"과 "허용 목록 외만 교정" 두 모드를 지원한다. 예: `keep_emphasis: true`면 강조 표시는 살리면서 글꼴·크기만 통일.
- 프리셋은 조직 표준(예: 공문서 서식)별로 여러 개 만들어 두고 선택한다.

## 6. 아키텍처

```
┌────────────────────────────────────────────┐
│  UI 레이어                                  │
│  v1: CLI (파일/폴더 + 프리셋 지정)            │
│  v2: 간단 GUI / MCP 서버                    │
├────────────────────────────────────────────┤
│  코어: 규칙 엔진                             │
│  - 프리셋 로더/검증                          │
│  - 문서 모델 순회 (표 → 셀, 텍스트 구간)      │
│  - 현재 서식 vs 규칙 비교 → 변경 목록 생성     │
│  - 리포트 생성                               │
├────────────────────────────────────────────┤
│  문서 엔진 (교체 가능한 어댑터)                │
│  v1: COM 어댑터 (pyhwpx/pywin32, 한글 제어)  │
│  v2: HWPX 어댑터 (zip+lxml 직접 조작)        │
└────────────────────────────────────────────┘
```

- **언어: Python** (hwp-mcp 선례, COM 접근 용이, 추후 MCP 서버화 쉬움)
- 규칙 엔진과 문서 엔진을 분리해 두는 것이 핵심 — COM으로 시작해도 나중에 HWPX 엔진을 끼워 넣을 수 있다.
- COM 어댑터 구현 메모:
  - `pyhwpx` 라이브러리 우선 검토 (표 순회, CellBorderFill, CharShape 액션 래핑 제공)
  - 보안 승인 모듈(FilePathCheckerModule) 등록으로 파일 접근 팝업 억제 (hwp-mcp 방식)
  - 한글 창은 숨김 모드로 실행, 처리 중 사용자 입력 충돌 방지

## 9. 확정 필요 사항 (사용자 결정 대기)

1. **실행 환경**: 사용 PC에 한글(한컴오피스)이 설치되어 있는가? 버전은? (COM 방식 전제 조건)
2. **대상 문서**: 주로 .hwp인가 .hwpx인가? 문서 1건당 표 개수·분량, 한 번에 처리할 파일 수 규모는?
3. **표준 서식 실제 값**: §5 프리셋 예시의 실제 값(선 굵기, 배경색, 글꼴, 크기 등). 기존 조직 표준 문서가 있으면 그것을 기준으로 추출 가능.
4. **UI 형태 우선순위**: CLI로 충분한가, 처음부터 간단한 GUI가 필요한가? (사용자가 본인 외 비개발자 동료도 포함되는지)
5. **글자 서식 정리 강도**: 문서 전체 글꼴·크기 강제 통일인가, 표 안만인가, 강조(진하게 등)는 보존인가?
